*jhv#mappings.txt*	Manipulate mappings.

Mappings sees maps as 2 types: keymaps and action maps.
key maps~
These map keys to a sequence of actions.  {lhs} will be prefixed with >
  <Plug>jhvtree:treename;keys
or nothing, if no tree.  The {rhs} will be a concatenation of action map
{lhs}s.  That is to say, {rhs} should look like >
  <Plug>jhvaction:treename:name:0;<Plug>jhvaction:treename:name:1;...
This structure allows easy management of actions per key map.
Because the keymap activates action maps, it MUST be recursive.  If any key
map does not follow this pattern, normalization consists of creating an action
map and then remapping the keymap to the corresponding action map.

action maps~
Action maps have {lhs} of the form: >
  <Plug>jhvaction:tree:name:uniq;
These mappings represent a single action to be performed.  tree and name
should not contain blanks, semicolons, or colons.  Semicolons and colons are
used as delimiters and blanks will break the {lhs} in a map command without
explicit escaping.  uniq is a unique string, currently implemented as an
incremented number.

Map trees~
Maps are grouped into "trees".  A tree consists of all mappings that begin
with the common prefix >
  <Plug>jhvtree:treename;
This includes all keymaps as well as the base keymap where keys is empty.
As a result, All mappings in a tree are |map-ambiguous| with each other.

The base keymap has no extra keys.  This map consists of only the prefix.
It is generally activated by default after 'timeout' and is designed in
such a way that it will continually activate itself.  The 'timeout' prevents
instant infinite recursion and allows sitting in a tree waiting for the next
keypress.

NOTE: 'timeout' is used to wait instead of something like |getchar()| because
|getchar()| moves the cursor into the statusline.  'timeout' does not, which
lets the user see where the cursor currently is while they decide what to
press next.

NOTE: the empty tree (no treename) acts like a global namespace and does not
have a base keymap.

Generally, RHS of all branches should also end with the common prefix.  This
allows activation of branch mappings by only typing the corresponding keys
without the prefix.  This gives behavior similar to a mode, where while
waiting on the prefix, for map disambiguation, tree branch maps can be taken.
After leaving the tree, the corresponding maps can no longer be activated by
their assigned key until after re-entering the tree (by typing the prefix).

entry maps~
Because the prefix starts with <Plug>, there is no "normal" way to enter the
tree.  Entry into the tree is generally done through entry maps.  These are
mappings of the form >
  *map <special> {lhs} <Plug>jhvtree:treename;keys
where {lhs} is some mapping without any <Plug>.  This gives the entire {lhs}
of a keymap which, as described above, should end with the tree prefix thus
performing the corresponding action and enterring the tree.

===Example===
Repeating mappings.
The repeat key (. by default) generally only repeats the previous subaction.
There is no native way to repeat an entire mapping.  However, keymaps and
trees can be used to create this behavior.

Suppose there is a tree named repeat.  The desired repeat key is <Space>.
Activate the map from outside the tree with <Leader>asdf
There is a base mapping: >
  *map <special> <Plug>jhvtree:repeat; {generated rhs}
a key map: >
  *map <special> <Plug>jhvtree:repeat;<Space>
  \ <Plug>jhvaction:repeat:myaction:0;<Plug>jhvtree:repeat;
an action map: >
  *map <special> <Plug>jhvaction:repeat:myaction:0;  dosomething
an entry map: >
  *map <special> <Leader>asdf <Plug>jhvtree:repeat;<Space>

When the user activates the entry map, the mapping expands to the keymap
{lhs}.  Because this is also recursive, it expands to the action map (and does
the action) followed by the tree prefix.  At this point, if 'timeout', then
the base mapping will just keep activating itself.  A single <Space> press
resolves to the keymap which again does the action and re-enters the tree.
When a different key is pressed, then the base mapping gets resolved to
nothing and the key does whatever it would normally do outside of any tree.
In this way, the {rhs} of the action map can be repeated with a single press
of <Space>.

===Functions===
						*jhv#mappings#CopyMap()*
|jhv#mappings#CopyMap(|mode, lhs, newlhs[, dict])
Copy the current mapping to {lhs} in the given mode to a {newlhs}.
dict can be provided as the result of |maparg(|lhs, mode, 0, 1) if the dict was
already calculated.  Otherwise, |maparg()| will be called.

						*jhv#mappings#ExtendMap()*
|jhv#mappings#ExtendMap(|...)
Add a mapping to the beginning or end of an existing mapping.
Arguments are strings that are concatenated together.  The final string should
look like >
    [setting=value]... *map <map-args> {lhs} {rhs}
Settings~
	before: bool=v:false, the new {rhs} should go before the original.
	keep: bool=v:false, Keep the lhs if no prior mapping.
	name: a name, defaults to {lhs}
	rep: bool=v:true, Handle |:Repeatable| mappings.
	SID: pass |expand(|'<SID>') to allow use of <SID> in {rhs}.
	verbose: bool=v:false, echom info

Implementation~
The {rhs} mappings will be assigned to an intermediate generated {lhs}.  This
intermediate mapping allows the user to freely use various `map-arguments`.
The generated intermediate {lhs} are concatenated and used as {rhs} for the
actual mapping bound to the desired {lhs}.  If the existing mapping is nore,
then the existing mapping is first mapped using a newly generated {lhs}.
This means there are 2 generated {lhs} (one for the original and one for the
current) which will be concatenated into the {rhs} for the mapping.

Generated {lhs} have the form "<Plug>ExtendMap:%(mapmode):%(count):%(name)"
where mapmode is the map prefix (ex. "i" for "imap", "" for "map"), count
is just an incremented counter to ensure the generated {lhs} does not yet
have an existing mapping, and name is the name setting.

Example~
Commands: >
	nnoremap doit :echo "doit"<CR>
	ExtendMap nnoremap doit :echo "I did it!"<CR>
<possible result: >
	nnoremap <Plug>ExtendMap:%(mapmode):%(count):%(name); :echo "doit"<CR>
	nnoremap <Plug>ExtendMap:%(mapmode):%(count):%(name); :echo "I did it!"<CR>
	nmap doit <Plug>ExtendMap:...;<Plug>ExtendMap:...;
<
Interaction with :Repeatable~
If the rep setting is v:true, then handle calculate the {lhs} of Mapping 2 of
the |:Repeatable| maps and extend that.  This way, the newly added {rhs} will
be repeated together with whatever was originally the {rhs}

						*jhv#mappings#Repeatable()*
This function creates the set of mappings to have repeatable mapping behavior.
It takes a single string argument of the form: >
	[setting=value ...] [<SNR>D_] *map [<map-args>...] {lhs} {rhs}
<If given multiple strings, they will effectively be |join()|ed with a single
space.

The string will be split into arguments which are sequences of non- whitespace
characters.  Any character following a backslash will be treated as part of an
argument.  Arguments will be parsed as settings from left to to right until
the first argument that does not match the setting=value pattern.

An exception is if the argument matches '<SNR>[0-9]\+_', in which case this is
assumed to be the value of `expand(`"<SID>") and is treated as the value of an
'SID=value' argument.  This allows specifying SID without the need for string
formatting or concatenation.

Setting values are decoded as JSON if possible and used as is otherwise.

The remaining text after the setting arguments is the raw map command.  Once
{rhs} is detected, there will be no more argument splitting and any whitespace
will be treated as part of the {rhs} argument.

settings~
	makemap: |Boolean| Create the main mapping and return "".  Otherwise,
		return a string with the mapping command for the user to |:exec|.
	mode: |string| the mode after the intial mapping.  Default to the
		* in *[nore]map, which is the map command used.
	name: |string| name for the mapping, which should be unique.
		Default to {lhs}.
	repeat: |string|, the key (sequence) to press to repeat the mapping.
		Defaults to "."
	SID: |string| Perform a simple substitution on any <SID> found in the
		mapping command with this value.
	transition: |string|, key-sequence to transition from mode back into
		initial mode.  Example: vmap ending in normal mode, transition
		might be something like '[v'] to highlight the region in visual
		mode.  This way, when the mapping is repeated, it is in the
		correct mode and rhs can be activated.  If omitted, then try
		making a best guess:
		map mode    default
		v   n       `<lt>v`>
		n   v       <C-\><C-N>
		i   n       a
		n   i       <C-\><C-N>
	verbose: |Boolean| echom commands for debugging.

Example 1 ~
Print reltime in normal mode after pressing "asdf". Repeat with "k".  >
	:Repeatable repeat=k nmap asdf :echo join(reltime(), ':')<CR>
<Example 2~
Use exec to repeat mappings containing <SID>. >
	function s:MyFunc()
		echo 'MyFunc was called!'
	endfunction
	exec 'Repeatable nmap asdf :call ' . expand('<SID>') . 'MyFunc()<CR>'
<I have not yet found a reliable way to detect the <SID> of where the user
command is called, so for mappings containing <SID>, options are using |:exec|
or the SID setting.

Details~
repeatable.vim works by creating various intermediate mappings:
1. *map %(lhs) <Plug>repeatable_map:%(mapmode):%(name);<Plug>repeatable_wait:%(mapmode):%(name);
2. *map <Plug>repeatable_map:%(mapmode):%(name); %(rhs)
3. %(mode)map <expr> <Plug>repeatable_wait:%(mapmode):%(name);
	\ getchar(1) == 0 ? "%(noop)\<Plug>repeatable_wait:%(mapmode):%(name);" : ""
4. %(mode)map <Plug>repeatable_wait:%(mapmode):%(name);$(repeat) %(transition)%(lhs)

%(varname) is replaced by whatever the setting is.
	lhs: lhs of the map commandline
	rhs: rhs of the map commandlin
	noop: a no-op key-sequence, "\<Ignore>" if available.
		Otherwise, a mapping to <Cmd>exec ''<CR> if <Cmd> is available
		Otherwise <silent> mappings:
			n -> :exec ''<CR>
			i -> <C-R>=''<CR>
			v -> g<C-G>
	mode: mode setting
	name: name setting
	mapmode: prefix of map command. example: for "inoremap", it will be "i"
		and for "map", it will be ""
	repeat: The repeat setting.
	transition: The transition setting.

How it works~
Mapping 1 activates mapping 2 and then enters mapping 3.
Mapping 2 just runs the {rhs} of the original mapping.
Mapping 3 is intentionally ambiguous with mapping 4.  As a result, vim will
	pause waiting for disambiguation between these two mappings.  If vim
	disambiguates to mapping 3, then that means no extra key was pressed.
	It first does an effective no-op command followed by re-enterring the
	ambiguous state.  The %(noop) is necessary because otherwise, the
	mapping would be left- |recursive_mapping| and it would just be taken
	literally without mapping.  An alternative could be an <expr> mapping
	that returns |nr2char(||getchar()|) so vim would continuously wait
	until getting a character.  However, |getchar()| moves the cursor into
	the status bar.  Using this recursive ambiguous method keeps the
	cursor in the current text position.
Mapping 4 just maps to mapping 1 after %(transition) to put vim back into the
	appropraite mode before re-activating {rhs}.

							*jhv#mappings#Tmap()*
jhv#mappings#Tmap(...)
Manage a tree of mappings.

Arguments are parsed with |jhv#parse#Settings()| except the first argument
which should be the name of the tree to use.  Besides the settings, TMap takes
a mapping and interprets it as a mapping of a tree.  An action map to the
{rhs} is created and the action is added to the keymap created from {lhs}.
If the base tree map does not already exist, it will be created.  Lastly,
depending on settings, an entry map might be created to perform the {rhs}
action and enter the tree.


settings:
  * tree: |str|, name of the tree.  As an alternative, the "tree=name" can be
    shortened to "=name" to specify the tree name.
  * enter: |str|, "[*[nore]map] [{lhs}] [{rhs}]".  If non-empty, then this is
    used to create an entry map.  the mapcmd and lhs will be taken from the
    main mapping if omitted.  rhs defaults to empty and will be used as a
    prefix before activating the keymap. Whitespace is required to
    differentiate lhs and rhs.
    Examples: >
      'imap lhs rhs'
      'lhs rhs'
      'imap  rhs'
      'imap lhs'
      'imap'
      'lhs'
      '  rhs'
<  * target: |str|, target tree to enter after the mapping.  This defaults to
    the current target if any, else the current tree.  If empty, then there is
    no target tree (explicitly exit the tree).
  * SID: sid to replace <SID> in the mapping.
  * verbose: bool, print map commands.
  * keep: bool, keep the existing keypresses if a map does not already exist.
  * add: |str|, <: add action before, >: add action after, =: replace existing
    action.  Default is =.

NOTE
types 4 and 1 must be in the same map mode.
type 3 could be in a different mode, but its action would need to different
from simply {type2}{type1}

Example~
Add mappings to indent the selected lines. >
	Tmap mytree emode=vnore rpre="'<lt>V'>" enter=> nnoremap <C-T> '<lt>V'>>
	Tmap mytree emode=vnore rpre="'<lt>V'>" enter=<lt> nnoremap <C-D> '<lt>V'><lt>
The mappings go into the "mytree" tree.  emode indicates that entry into this
tree should be via a vnoremap command. The rpre modifies the map {rhs} by
removing the '<lt>V' from the beginning and uses that as the entry map {rhs}.
enter determines the key sequence to enter the "mytree" tree (< or >).
Finally, the nnoremap uses <C-T> and <C-D> to select the last selected range
and then shift them left or right accordingly.

NOTE: Repeatable is basically the same as a tree with only a single branch.


===Helper Functions===
							*jhv#mappings#Map2Estr()*
jhv#mappings#Map2Estr(mpcmd, quote=1)
Return a string that can be |eval()|ed as the string representation of the
map key sequence.
Example: >
	eval(jhv#mappings#Map2Estr('<C-X>\')) == "\<C-X>\\"
This is useful for creating strings that can be used with exec. or eval
Return a string that would evaluate to a:mpcmd when passed to |eval()|.
If quote, then the string is also surrounded with double quotes.  Otherwise
the quotes are omitted.  This is useful if the result is intended for use
inside a string such as: >
	eval(printf('"%s %s..."', jhv#mappings#Map2Estr('<C-X>\', 0), ...))
<

							*jhv#mappings#Str2Map()*
jhv#mappings#Str2Map(mpstr)
Convert a str into an appropriate string for use in the {rhs} of a mapping to
retain the original value.  Basically, convert specific characters to their
<Name> format so when used as RHS of an <expr> mapping, the string will not
change meaning.
