*jhv#mappings.txt*	Manipulate mappings.

===User Commands===
								*:CopyMap*
:CopyMap mode lhs newlhs
Pass arguments to |jhv#mappings#CopyMap()|.

								*:ExtendMap*
:ExtendMap [setting=value ...] *map [<map-args...] {lhs} {rhs}
This is the User command version of |jhv#mappings#ExtendMap()|. All arguments
are treated as a single string and passed to that function.

								*:Repeatable*
:Repeatable [setting=value ...] *map [<map-args>...] {lhs} {rhs}
This is the User command version of |jhv#mappings#Repeatable()|.  All arguments
are treated as a single string and passed to |jhv#mappings#Repeatable()|.



===Functions===
						*jhv#mappings#CopyMap()*
jhv#mappings#CopyMap(mode, lhs, newlhs)
Copy the current mapping to {lhs} in the given mode to a {newlhs}.  This saves
a copy of the mapping at the time of this call to {newlhs}.  Changes to the
original {lhs} mapping will NOT be reflected in the {newlhs} mapping.

						*jhv#mappings#ExtendMap()*
This function adds a mapping command to the left or right of an existing map
command.  If the map does not already exist, it will be created.

Settings~
	before: bool=v:false, the new {rhs} should go before the original.
	keep: bool=v:false, Keep the lhs if no prior mapping.
	name: a name, defaults to {lhs}
	rep: bool=v:true, Handle |:Repeatable| mappings.
	SID: pass |expand(|'<SID>') to allow use of <SID> in {rhs}.
	verbose: bool=v:false, echom info

Implementation~
The {rhs} mappings will be assigned to an intermediate generated {lhs}.  This
intermediate mapping allows the user to freely use various `map-arguments`.
The generated intermediate {lhs} are concatenated and used as {rhs} for the
actual mapping bound to the desired {lhs}.  If the existing mapping is nore,
then the existing mapping is first mapped using a newly generated {lhs}.
This means there are 2 generated {lhs} (one for the original and one for the
current) which will be concatenated into the {rhs} for the mapping.

Generated {lhs} have the form "<Plug>ExtendMap:%(mapmode):%(count):%(name)"
where mapmode is the map prefix (ex. "i" for "imap", "" for "map"), count
is just an incremented counter to ensure the generated {lhs} does not yet
have an existing mapping, and name is the name setting.

Example~
Commands: >
	nnoremap doit :echo "doit"<CR>
	ExtendMap nnoremap doit :echo "I did it!"<CR>
<possible result: >
	nnoremap <Plug>ExtendMap:%(mapmode):%(count):%(name); :echo "doit"<CR>
	nnoremap <Plug>ExtendMap:%(mapmode):%(count):%(name); :echo "I did it!"<CR>
	nmap doit <Plug>ExtendMap:...;<Plug>ExtendMap:...;
<
Interaction with :Repeatable~
If the rep setting is v:true, then handle calculate the {lhs} of Mapping 2 of
the |:Repeatable| maps and extend that.  This way, the newly added {rhs} will
be repeated together with whatever was originally the {rhs}

						*jhv#mappings#Repeatable()*
This function creates the set of mappings to have repeatable mapping behavior.
It takes a single string argument of the form: >
	[setting=value ...] [<SNR>D_] *map [<map-args>...] {lhs} {rhs}
<If given multiple strings, they will effectively be |join()|ed with a single
space.

The string will be split into arguments which are sequences of non- whitespace
characters.  Any character following a backslash will be treated as part of an
argument.  Arguments will be parsed as settings from left to to right until
the first argument that does not match the setting=value pattern.

An exception is if the argument matches '<SNR>[0-9]\+_', in which case this is
assumed to be the value of `expand(`"<SID>") and is treated as the value of an
'SID=value' argument.  This allows specifying SID without the need for string
formatting or concatenation.

Setting values are decoded as JSON if possible and used as is otherwise.

The remaining text after the setting arguments is the raw map command.  Once
{rhs} is detected, there will be no more argument splitting and any whitespace
will be treated as part of the {rhs} argument.

settings~
	makemap: |Boolean| Create the main mapping and return "".  Otherwise,
		return a string with the mapping command for the user to |:exec|.
	mode: |string| the mode after the intial mapping.  Default to the
		* in *[nore]map, which is the map command used.
	name: |string| name for the mapping, which should be unique.
		Default to {lhs}.
	repeat: |string|, the key (sequence) to press to repeat the mapping.
		Defaults to "."
	SID: |string| Perform a simple substitution on any <SID> found in the
		mapping command with this value.
	transition: |string|, key-sequence to transition from mode back into
		initial mode.  Example: vmap ending in normal mode, transition
		might be something like '[v'] to highlight the region in visual
		mode.  This way, when the mapping is repeated, it is in the
		correct mode and rhs can be activated.  If omitted, then try
		making a best guess:
		map mode    default
		v   n       `<lt>v`>
		n   v       <C-\><C-N>
		i   n       a
		n   i       <C-\><C-N>
	verbose: |Boolean| echom commands for debugging.

Example 1 ~
Print reltime in normal mode after pressing "asdf". Repeat with "k".  >
	:Repeatable repeat=k nmap asdf :echo join(reltime(), ':')<CR>
<Example 2~
Use exec to repeat mappings containing <SID>. >
	function s:MyFunc()
		echo 'MyFunc was called!'
	endfunction
	exec 'Repeatable nmap asdf :call ' . expand('<SID>') . 'MyFunc()<CR>'
<I have not yet found a reliable way to detect the <SID> of where the user
command is called, so for mappings containing <SID>, options are using |:exec|
or the SID setting.

Details~
repeatable.vim works by creating various intermediate mappings:
1. *map %(lhs) <Plug>repeatable_map:%(mapmode):%(name);<Plug>repeatable_wait:%(mapmode):%(name);
2. *map <Plug>repeatable_map:%(mapmode):%(name); %(rhs)
3. %(mode)map <expr> <Plug>repeatable_wait:%(mapmode):%(name);
	\ getchar(1) == 0 ? "%(noop)\<Plug>repeatable_wait:%(mapmode):%(name);" : ""
4. %(mode)map <Plug>repeatable_wait:%(mapmode):%(name);$(repeat) %(transition)%(lhs)

%(varname) is replaced by whatever the setting is.
	lhs: lhs of the map commandline
	rhs: rhs of the map commandlin
	noop: a no-op key-sequence, "\<Ignore>" if available.
		Otherwise, a mapping to <Cmd>exec ''<CR> if <Cmd> is available
		Otherwise <silent> mappings:
			n -> :exec ''<CR>
			i -> <C-R>=''<CR>
			v -> g<C-G>
	mode: mode setting
	name: name setting
	mapmode: prefix of map command. example: for "inoremap", it will be "i"
		and for "map", it will be ""
	repeat: The repeat setting.
	transition: The transition setting.

How it works~
Mapping 1 activates mapping 2 and then enters mapping 3.
Mapping 2 just runs the {rhs} of the original mapping.
Mapping 3 is intentionally ambiguous with mapping 4.  As a result, vim will
	pause waiting for disambiguation between these two mappings.  If vim
	disambiguates to mapping 3, then that means no extra key was pressed.
	It first does an effective no-op command followed by re-enterring the
	ambiguous state.  The %(noop) is necessary because otherwise, the
	mapping would be left- |recursive_mapping| and it would just be taken
	literally without mapping.  An alternative could be an <expr> mapping
	that returns |nr2char(||getchar()|) so vim would continuously wait
	until getting a character.  However, |getchar()| moves the cursor into
	the status bar.  Using this recursive ambiguous method keeps the
	cursor in the current text position.
Mapping 4 just maps to mapping 1 after %(transition) to put vim back into the
	appropraite mode before re-activating {rhs}.

===Helper Functions===
							*jhv#mappings#LHS2eval()*
jhv#mappings#LHS2eval(mpcmd, quote=1)
Return a string that would evaluate to a:mpcmd when passed to |eval()|.
If quote, then the string is also surrounded with double quotes.  Otherwise
it is given unquoted for insertion into a str.  Add backslashes in front of
quotes and backslashes.  Also convert key-notation "<...>" to "\<...>".

							*jhv#mappings#eval2RHS()*
jhv#mappings#eval2RHS(mpstr)
Convert a str into an appropriate string for use in the {rhs} of a mapping.
Even when expr, {rhs} is still evaluated as a mapping so <lt> should be used
in place of a single <.
