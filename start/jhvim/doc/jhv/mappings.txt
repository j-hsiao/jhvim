*jhv#mappings.txt*	Manipulate mappings.

Mappings sees maps as 2 types: keymaps and action maps.
key maps~
These map keys to a sequence of actions.  {lhs} will be prefixed with >
  <Plug>jhvtree:treename;keys
or nothing, if no tree.  The {rhs} will be a concatenation of action map
{lhs}s.  That is to say, {rhs} should look like >
  <Plug>jhvaction:treename:name:0;<Plug>jhvaction:treename:name:1;...
This structure allows easy management of actions per key map.
Because the keymap activates action maps, it MUST be recursive.  If any key
map does not follow this pattern, normalization consists of creating an action
map and then remapping the keymap to the corresponding action map.

action maps~
Action maps have {lhs} of the form: >
  <Plug>jhvaction:tree:name:uniq;
These mappings represent a single action to be performed.  tree and name
should not contain blanks, semicolons, or colons.  Semicolons and colons are
used as delimiters and blanks will break the {lhs} in a map command without
explicit escaping.  uniq is a unique string, currently implemented as an
incremented number.

Map trees~
Maps are grouped into "trees".  A tree consists of all mappings that begin
with the common prefix >
  <Plug>jhvtree:treename;
This includes all keymaps as well as the base keymap where keys is empty.
As a result, All mappings in a tree are |map-ambiguous| with each other.

The base keymap has no extra keys.  This map consists of only the prefix.
It is generally activated by default after 'timeout' and is designed in
such a way that it will continually activate itself.  The 'timeout' prevents
instant infinite recursion and allows sitting in a tree waiting for the next
keypress.

NOTE: 'timeout' is used to wait instead of something like |getchar()| because
|getchar()| moves the cursor into the statusline.  'timeout' does not, which
lets the user see where the cursor currently is while they decide what to
press next.

NOTE: the empty tree (no treename) acts like a global namespace and does not
have a base keymap.

Generally, RHS of all branches should also end with the common prefix.  This
allows activation of branch mappings by only typing the corresponding keys
without the prefix.  This gives behavior similar to a mode, where while
waiting on the prefix, for map disambiguation, tree branch maps can be taken.
After leaving the tree, the corresponding maps can no longer be activated by
their assigned key until after re-entering the tree (by typing the prefix).

entry maps~
Because the prefix starts with <Plug>, there is no "normal" way to enter the
tree.  Entry into the tree is generally done through entry maps.  These are
mappings of the form >
  *map <special> {lhs} <Plug>jhvtree:treename;keys
where {lhs} is some mapping without any <Plug>.  This gives the entire {lhs}
of a keymap which, as described above, should end with the tree prefix thus
performing the corresponding action and enterring the tree.

===Example: Repeating mappings.===
The repeat key (. by default) generally only repeats the previous subaction.
There is no native way to repeat an entire mapping.  Use a treemap to
attain this behavior.

Desired mapping: <Leader>asdf
Desired repeat key: <Space>

1. Pick a name for the tree (here we choose "repeat")
2. Add an action map >
	nnoremap <Plug>jhvaction:repeat:myaction:##; {rhs}
3. Add a tree map <Plug>jhvtree:repeat;
4. Add a key map: >
	nmap <Plug>jhvtree:repeat;<Space>
	\ <Plug>jhvaction:repeat:myaction:##;<Plug>jhvtree:repeat;
5. Add an entry map: >
	nmap <Leader>asdf <Plug>jhvtree:repeat;<Space>

From normal mode, the user can activate the mapping with <Leader>asdf which
recursively activates the key map.  The keymap activates the action map
performing whatever action was desired and then enters the "repeat" tree.
On the next press of <Space> it is disambiguated into the keymap which
activates the action and then enters the "repeat" tree again.  On a different
keypress, the tree is disambiguated as a no-op and the new key is interpreted
by itself.

===User Commands===
The user commands are provided as more convenient ways to call the
corresponding function.

command     function
*:CopyMap*    |jhv#mappings#Copymap()|
*:TMap*       |jhv#mappings#TMap()|

===Functions===
						*jhv#mappings#CopyMap()*
|jhv#mappings#CopyMap(|mode, lhs, newlhs[, dict])
Copy the current mapping to {lhs} in the given mode to a {newlhs}.
dict can be provided as the result of |maparg(|lhs, mode, 0, 1) if the dict was
already calculated.  Otherwise, |maparg()| will be called.  If there is no
mapping to copy, then create a non-recursive mapping from {newlhs} to {lhs}.


							*jhv#mappings#TMap()*
jhv#mappings#TMap(...)
Add mappings to a tree.

Arguments are parsed with |jhv#parse#Settings()| with the additional
allowance of a tree name as a bare first argument.  Following the settings
should be a map command as it would normally appear in a script.  TMap will
parse the mapping command and generate the corresponding tree, key, action,
and entry maps if needed.

settings:
  * tree: |str|, name of the tree.  As an alternative, the "tree=name" can be
    shortened to "=name" to specify the tree name.  It can also be given as
    the first argument without any =.
  * enter: |str|, "[*[nore]map] [{lhs}] [{rhs}]".  If non-empty, then this is
    used to create an entry map.  The mapcmd and lhs will be taken from the
    main mapping if omitted.  rhs defaults to empty and will be used as a
    prefix before activating the keymap. When omitting {lhs}, whitespace
    before {rhs} is required.  Otherwise, it will be parsed as {lhs}.
    Examples: >
      'imap lhs rhs'
      'lhs rhs'
      'imap  rhs'
      'imap lhs'
      'imap'
      'lhs'
      ' rhs'
<  * target: |str|, target tree to enter after the mapping.  This defaults to
    the current target of an existing keymap if any. Otherwise, use the
    current tree.  Specify an empty target to explicitly exit the tree.
    The base tree map is only generated if this matches tree.
  * SID: sid to replace <SID> in the mapping.  Generally this will be
    specified as: >
    expand('<SID>')
<    This is only necessary if the mapping has <SID> in it.
  * verbose: bool, print map commands.
  * keep: bool, keep the default keypress actions if no prior mapping exists.
    This is useful to add actions on top of the default action.
  * add: |str|, <: add action before, >: add action after, =: replace existing
    action.  Default is =.
  * name: |str| A name for the action.  If omitted, then use {lhs} to generate
    a name.

Example~
Add mappings to indent the selected lines >
	TMap mytree enter='vnoremap > :<CR>' nnoremap <C-T> '<lt>V'>>
	TMap mytree enter='vnoremap <lt> :<CR>' nnoremap <C-D> '<lt>V'><lt>
The enter settings indicate that the tree should be enterred via < and > in
visual mode.  At that point, :<CR> will be run only during the entry map.
This puts vim in a state where the nnoremap <C-T> can be used to indent
the selected lines after which the default tree (the current tree) is entered.
At that point, any <C-T> or <C-D> can be used to indent/dedent the same
previously-selected lines.
NOTE This is similar to >
	TMap mytree enter= nnoremap <C-T> '<lt>V'>>
	TMap mytree enter= nnoremap <C-D> '<lt>V'><lt>
	TMap mytree target=mytree vnoremap > >
	TMap mytree target=mytree vnoremap <lt> <lt>
except this second version creates more mappings since there are now base tree
maps for both normal and visual modes.
